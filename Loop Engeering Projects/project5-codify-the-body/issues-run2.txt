Project 1/stop-watch.sh reports "Stopped long-task.sh" and deletes long-task.pid immediately after `kill "$pid"` returns success, without confirming the process actually exited — kill returning 0 only means the signal was delivered, not that the process died (e.g. if it ignores SIGTERM), so the script can wrongly report success while the process keeps running.
project3-morning-brief/morning_brief.py's main() lets append_to_done()'s ValueError (raised when progress.md is missing a "## Done" section) propagate as a raw, unhandled traceback instead of catching it and printing a clean, actionable error message.
project2-make-tests-pass/test_calc_utils.py has no test at all for add() beyond two integer cases (add(2,3) and add(-1,1)); nothing exercises a float input (e.g. add(1.5, 2.5) should equal 4.0), so a regression that broke float handling would go undetected. Add a test covering a float case.
