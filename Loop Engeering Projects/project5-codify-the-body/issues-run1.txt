project3-morning-brief/morning_brief.py's find_todos() sorts items as full "path:line: text" strings, so within the same file, line numbers sort lexicographically rather than numerically — e.g. "file.py:10: ..." sorts before "file.py:2: ..." because "1" < "2" as characters. Fix it to sort by (relpath, line number) instead of the final formatted string.
Project 1/long-task.sh never removes a stale done.txt left over from a previous run before starting its sleep, so a process polling for done.txt right after long-task.sh starts can see the OLD file and wrongly conclude the new run already finished.
project2-make-tests-pass/calc_utils.py's add(a, b) has no input validation, so calling it with non-numeric arguments (e.g. add("1", "2")) silently returns string concatenation ("12") instead of a numeric sum or a clear error — inconsistent with is_palindrome and factorial in the same file, which both now validate their input explicitly.
